# 최종뎀 환산 효율과 입력 수집

## 근거와 적용 범위

- 공식 스탯 연산: https://maplestory.nexon.com/Guide/N23GameInformation/Articles/390 (확인일 2026-10-11). 상담 때 변경된 규칙을 확인한다.
- 8항 기본식과 수치 예제: https://www.fmkorea.com/8336709224 (2026-10-11 사용자가 제공한 본문 기준; 사이트 원문은 직접 조회하지 못함).
- 환산 입력 조건: https://maplescouter.com/ko/input (확인일 2026-10-11). 노도핑·링크·스택·직업별 상태 등 비교하려는 사이트 조건을 실제 입력과 맞춘다.

결과는 **동일 조건의 데미지 비율을 최종뎀으로 환산한 증가율**이다. 스탯창 최종뎀 변화, 절대 환산주스탯, 전투력, 클리어 가능 여부와 구분한다. `damage-v2-eight-factors`는 기본식을 계산하며 환산의 모든 직업 사이클·HEXA·도핑·쿨감 모델을 자동 복제하지 않는다. 외부 실측 비교가 없으면 환산과의 오차는 미검증이라고 밝힌다.

## 계산 순서와 도구 선택

1. 실제 캐릭터 효율 상담이면 캐릭터·목표·프리셋·버프·대상·기준 시각을 확인한다. 단순 공식 예제에는 전체 캐릭터 상담을 요구하지 않는다.
2. `get_damage_calculation_context(character_name=..., inputs=...)`로 기본 정보와 스탯을 수집한다. 기본 조회는 `basic`, `stat` 두 항목이다. 필요한 장비·심볼·하이퍼스탯·링크·유니온 등만 `additional_sections`에 지정한다. 저장된 API만 재사용하려면 `refresh=False`로 호출하고 기준일을 밝힌다. 이 도구는 화면을 캡처하지 않는다.
3. `missing_fields`, `consistency_issues`, `breakdown_missing_fields`를 읽고 부족한 값만 사용자에게 묻거나 관련 API로 확인한다. `status='needs_input'`이면 계산 가능한 실제 캐릭터 입력이라고 표현하지 않는다.
4. 확인된 전후 총합은 `calculate_final_damage_gain`, 옵션 증가·교체량은 `calculate_final_damage_option_gain`을 호출한다. 서버가 옵션 변화에서 교체 후 값을 계산한다. 스킬별 조건이 다르면 `calculate_skill_damage_comparison`으로 비교한다.
5. 같은 조건의 환산 비교값이 있으면 `reference`를 함께 전달한다. 차이가 크면 입력·조건·직업 예외를 조사하며 결과를 맞추기 위한 임의 보정계수를 넣지 않는다.

## API와 사용자 입력의 경계

`final_stat`의 스탯, 공격력/마력, 데미지·보공·일몹뎀, 크확·크뎀·최종뎀·방무는 **이미 적용된 총합**으로 취급한다. 장비·링크·유니온·코어의 포함된 효과를 다시 더하지 않는다. 스탯명 누락·중복·파싱 실패는 모르는 값이며 0으로 채우지 않는다. 실제 효과가 없음을 확인한 경우에만 0/빈 목록을 쓴다.

수집 입력 `inputs`:

- `stat_weights`: 검증한 직업별 스탯 계수. 일반 STR 직업 예: `{'STR':4,'DEX':1}`. 제논은 검증한 각 스탯 계수, 데몬어벤져는 별도로 검증한 `stat_factor`를 전달한다. HP×4로 추정하지 않는다. 서버에는 자동 직업 공식 표가 없다.
- `attack_stat`: `공격력` 또는 `마력`. `attack_power`로 확인한 총합을 직접 전달할 수도 있다.
- `weapon_constant`, `elemental_ignore_percent`: 확인한 무기상수·해당 속성의 유효 내성 무시 총합. API에 없으면 사용자 또는 현재 직업 근거로 보완한다. 공식 가이드의 일반 속성 내성 무시는 합산이며 직업 예외를 확인한다. 글의 모든 항을 무조건 곱연산으로 처리하지 않는다.
- 스탯별 전체 % `stat_percent_bonuses`, 전체 %미적용 수치 `stat_flat_after_percent`, 공/마 % `attack_percent_bonus`, %미적용 공/마 `attack_flat_after_percent`. % 옵션 비교에 필요하다. 심볼·장비 부분합을 전체 미적용 값으로 간주하지 않는다. 직업 패시브·하이퍼·유니온·버프·어빌리티 예외를 함께 확인한다.
- `conditions`: 프리셋·버프·스택·대상·측정 조건 설명. API 없는 수동 입력은 `data_as_of`에 관찰 날짜 또는 ISO 시각을 반드시 넣는다. 다른 기준일의 API와 섞지 않는다.
- 부족한 공통 스탯은 동일 이름 필드로 직접 보완한다. `field_provenance`의 API/클라이언트 입력과 시각을 확인한다. 클라이언트 입력을 공식 API가 검증한 값이라고 표현하지 않는다.

전체 %·미적용 값이 확인되면 `detailed_profile`을 만든다. API 총합에서 역산한 기초값은 총합에 맞춘 값이며 반올림 전 실제 기초 스탯과 같다고 보장하지 않는다. 효율에 영향을 주면 직접 입력이나 정확한 관찰로 보완한다.

## 8항 공식

모든 % 입력은 30%를 `30`으로 전달한다.

```text
A = Σ 직업계수 × [(%적용 스탯) × (1+스탯%/100) + %미적용 스탯]
B = 무기상수
C = (%적용 공/마) × (1+공/마%/100) + %미적용 공/마
D = 1 + (데미지% + (보스면 보공%, 일반 몬스터면 일몹뎀%))/100
E = ∏(1+독립 최종뎀%/100)
F = max(0, 1 - 대상 방어율/100 × ∏(1-독립 방무%/100))
G = 1 + 크확/100 × (0.35+추가 크뎀/100)
H = 1 - 대상 속성 내성/100 × (1-유효 속성 내성 무시/100)
지표 = A × B × C × D × E × F × G × H × 확인한 전투 배율
증가율(%) = (교체 후 지표/교체 전 지표 - 1) × 100
```

기본식의 A에는 `/100`이 있으나 비율에서 상쇄되므로 `stat_factor`에는 적용하지 않는다. 크확 100%에서 G는 본문과 같은 `1.35+추가 크뎀/100`이다. 초과 크확은 일반 상한 100이며 다른 효과로 전환하는 직업·스킬은 별도 반영한다. 평균 크리티컬 35%는 기본 20~50%의 평균이다.

본문 요약의 `+` 표기는 곱셈 본문을 따른다. 글의 ‘보스 방무 300%’는 대상 **방어율**이다. 보공과 일몹뎀을 동시에 적용하지 않는다. 이미 최종뎀을 포함한 스탯 공격력에 최종뎀을 다시 곱하지 않는다. 전투력·스탯 공격력을 공격력/마력 총합에 넣지 않는다.

## 프로필과 옵션 변화

`DamageProfile`은 적용된 `stat_factor`, `attack_power` 총합을 사용한다. `DetailedDamageProfile`은 `stat_terms=[{name, coefficient, value}]`, `attack`을 사용한다. 각 `value`는 `percent_affected`, `percent_bonus`, `flat_after_percent`, 선택적 `rounding`(`none` 또는 검증된 `floor`)이다. 전체 % 적용 범위가 없으면 총합에 %를 곱하여 옵션 효율을 만들어내지 않는다.

공통 프로필은 `damage_percent`, `boss_damage_percent`, `normal_monster_damage_percent`, `critical_rate_percent`, `critical_damage_percent`, `final_damage_sources`, `ignore_defense_sources`를 모두 지정한다. 상세 프로필에는 `weapon_constant`, `elemental_ignore_percent`도 필수다. 총합 프로필의 무기상수/전투 배율 기본값 1은 동일 조건이 상쇄되는 정규화 비교용이다. `combat_multiplier`는 확인한 스킬 배율·사용 횟수·숙련도·포스·레벨 등 추가 배율에만 사용하고 이미 포함된 항을 중복 곱하지 않는다.

- 독립 최종뎀 `[20,10]`은 1.32. 합산 스탯창 32%를 쓰면 `[32]`만 넣는다. 합연산 그룹은 먼저 그룹 전후 수치를 산출한다.
- 독립 방무 `[90,30]`은 93%. 합산 방무와 포함된 항을 중복 입력하지 않는다. 반올림된 총합의 오차를 밝힌다.
- 옵션 도구 `change`에는 `attack_percent_delta`, `stat_percent_deltas={'STR':...}`, %적용/미적용 스탯·공/마 증가량과 데미지·보공·크뎀 등의 `*_delta`를 전달한다. 스탯·공/마 옵션은 상세 프로필이 필요하며 미적용 부분은 별도 증가가 없으면 그대로 유지한다.
- 방무·독립 최종뎀 추가는 `add_ignore_defense_sources`, `add_final_damage_sources`; 교체는 `remove_*`로 실제 포함된 기존 항을 함께 제거한다. 총 방무 93%에서 30% 제거·40% 추가는 94%다. 방무 100% 항을 제거한 나머지는 총합만으로 역산할 수 없으므로 확인한 전후 프로필을 직접 준다.
- 무기상수 변경은 `weapon_constant_after`, 확인한 추가 전투 배율은 `additional_combat_multiplier`. 장비·스킬 변화도 함께 확인한다.

모든 계산 도구는 `target_defense_percent`, `is_boss`, `character_name`, `data_as_of`, `source_urls`, `rules_as_of`, `assumptions`를 받는다. 대상 방어율을 임의로 300%로 가정하지 않는다. 속성 무시가 변하면 `target_elemental_resistance_percent`가 필수다. 속성 항 생략은 동일 조건이 상쇄될 때만 사용한다. 비용은 확인한 `cost_meso`, 무료는 0, 모르면 생략한다.

## 스킬 가중 비교와 환산 대조

스킬 비교 `skills`는 `skill_name`, 기존 `baseline_damage_share_percent`, 스킬별 `before`, `after`를 포함한다. 동일 기간의 기존 점유율 합계가 100%여야 한다. 스킬별 증가비율을 기존 데미지 점유율로 가중하며 방무를 평균내지 않는다. 사용 횟수 변화는 검증한 전투 배율로 반영한다. 임의 점유율·누락 스킬·기존 피해 0인 새 스킬·미검증 쿨감으로 사이트 사이클을 재현했다고 주장하지 않는다.

`reference={label, source_url, gain_percent, conditions, max_gain_difference_pp}`는 같은 조건의 외부 증가율이다. 기본 허용차는 0.05 **퍼센트포인트**이며 정확도 보장이 아닌 대조 기준이다. `reference_check`에 증가율 차이와 데미지 비율 상대 오차가 나온다. `within_tolerance`는 전달한 사례 하나의 일치만 뜻하며 서버가 외부 사이트나 조건을 검증했다는 뜻이 아니다.

대조 전 KMS 버전·직업·캐릭터·프리셋·도핑·버프/스택·대상 방어율/속성·스킬/HEXA·반지·사이클과 옵션 증가/교체 여부를 맞춘다. 입력 보완 → 직업/스킬 예외 확인 → 점유율 검증 순서로 조사한다. 사이트의 반올림된 효율 한 줄만으로 기초 입력을 역산하거나 일치했다고 선언하지 않는다. 실제 환산 대조가 없으면 아래 예제 통과와 별개로 명시한다.

본문 예제 회귀 검증(기재 조건만 적용):

| 변화 | 최종뎀 환산 증가율 |
| --- | ---: |
| 공% 30 → 39, 미적용 공 0 | 6.923076923% |
| 합산 데미지% 150 → 159 | 3.6% |
| 기존 최종뎀 2%에 독립 3% 추가 | 3% |
| 대상 방어율 300%, 방무 80%에 30% 추가 | 45% |
| 같은 대상, 방무 95%에 30% 추가 | 5.294117647% |
| 크확 100%, 추가 크뎀 0 → 10 | 7.407407407% |
| 대상 속성 내성 50%, 무시 0 → 5 | 5% |

## 상담 결론

`undefined_baseline`은 기존 피해 지표가 0이라 증가율을 정의할 수 없는 경우다. 0% 증가로 해석하지 않는다. `gain_percent_per_100m_meso`는 1억 메소당 증가율이며 무료·비용 미확인은 null이다. 무료 대안을 버리지 않는다. 강화 기대비용은 평균이며 성공·클리어를 보장하지 않는다.

성장 단계·목표·시간·예산과 다시 대조한다. 생존·유틸·원킬·패턴·투자 시점까지 고려한다. 숫자가 커도 목표의 병목을 해결하지 못하면 우선 추천하지 않는다. 검증 범위와 불확실성은 짧게 밝힌다.
