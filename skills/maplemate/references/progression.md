# 성장 진단과 단계 선택

이 구분은 MapleMate의 상담용 판단 틀이다. 공식 등급이나 전체 커뮤니티의 합의가 아니다. 조사 근거와 한계는 [커뮤니티 조사](community.md)를 참고한다. MCP에서는 `get_maple_advice_guide(topic='progression')`로 읽는다.

## 1. 질문의 범위부터 정하기

“보공과 방무 차이”, “명시한 강화 조건의 평균 비용”에는 해당 설명·계산만 한다. “무엇부터 키울까”, “이걸 살까”, “이 보스가 될까”처럼 개인의 선택을 바꾸는 질문에는 성장 진단을 적용한다. 사용자가 원치 않는 전체 계정 평가로 확대하지 않는다.

기존 대화와 `get_player_state`에서 이미 확인한 목표·시간·예산을 재사용한다. 최신 캐릭터 이름을 명시하거나 최근 화면 관찰을 사용한다. 질문에 필요한 API만 조회하며 이름 호출 자체로 캡처하지 않는다. 핵심 미확인 항목은 “어떤 보스를 혼자/파티로 목표로 하나요? 평소 플레이 시간과 이번에 쓸 예산은 어느 정도인가요?”처럼 묶어 짧게 묻고, 독립적으로 확인할 수 있는 정보는 계속 확인한다.

## 2. 서로 다른 축을 합치지 않기

| 축 | 확인할 내용 | 확인 방법과 한계 |
| --- | --- | --- |
| 캐릭터 기반 | 직업·레벨·전직, 장비 균형과 기간제 여부, 스탯·포스·코어 | `basic`, `item-equipment`, 필요한 `stat`·`symbol-equipment`·`vmatrix`·`hexamatrix`; 만료·프리셋이 불명확하면 화면/사용자 확인 |
| 계정 기반 | 목표에 필요한 링크·유니온·아티팩트·챔피언 등 | 해당 API를 필요한 만큼 조회; 다른 캐릭터 전체 목록을 기본 수집하지 않음 |
| 콘텐츠 경험 | 안정적으로 하는 콘텐츠, 목표 보스의 난이도·인원·클리어/실패 상황 | 사용자 설명과 제공한 기록; 전투력·무릉 기록·연무장 결과만으로 실제 보스 경험을 확정하지 않음 |
| 시스템 이해 | 강화·프리셋·코어 이해, 해당 직업/보스의 경험 | 질문 내용과 사용자 설명; 플레이 연수·과금액으로 추정하지 않음 |
| 목표와 기간 | 레벨/지역, 솔플/파티 보스, 편안한 일퀘, 사냥 수익, 부캐, 코디·수집 | 사용자의 선택; 스펙업이나 최상위 보스가 모든 사람의 목표는 아님 |
| 제약 | 일/주 플레이 시간, 집중 사냥 가능 시간, 이번 메소 한도·추가 지출 의향·손실 허용 | 사용자 입력 우선; 메소 관찰값은 현재 전체 예산이 아니며 유료 이용을 가정하지 않음 |

환산 등 외부 지표를 사용자가 제공하면 계산기 종류·버전/시각·프리셋·버프 조건을 확인한다. 전투력에서 환산을 만들어내지 않는다. 해방 여부·퀘스트 단계는 API에 없거나 확실하지 않으면 사용자에게 확인한다. 계정 업적이 특정 캐릭터의 현재 진행 상태를 대신하지 않는다.

## 3. 성장 단계 고르기

| 단계 | 함께 관찰되는 신호 | 적용할 전략 |
| --- | --- | --- |
| 뉴비 / 기반 구축 | 목표 콘텐츠에 필요한 기본 세팅·코어·포스가 비어 있거나, 기간제 보상 이후의 유지 계획·기본 루틴이 아직 없음 | [beginner.md](beginner.md): 정착 또는 기본기 구축 |
| 중급 / 안정화·전환 | 현재 콘텐츠를 반복할 기반이 있고, 다음 보스·지역·세트 전환·해방 등의 병목과 우선순위를 비교하는 중 | [intermediate.md](intermediate.md): 안정화 또는 목표 전환 |
| 숙련 / 최적화·도전 | 해당 목표의 기본 요건과 성장 루틴이 갖춰져, 작은 투자 차이·스킬 운영·파티 역할·장기 세팅을 비교하는 중 | [advanced.md](advanced.md): 최적화 또는 상위 도전 |

목표와 관련된 장비·내실 및 실제 콘텐츠 경험의 근거를 함께 대조한다. 특정 레벨·별 수·환산·보스 한 마리로 자동 승급시키지 않는다. 미확인값 때문에 단계가 달라질 수 있으면 “장비 기반은 중급으로 보이지만 코어와 보스 경험은 확인이 필요하다”처럼 범위를 밝힌다. 자료가 없다는 이유로 부족하다고 판정하지 않는다.

시스템 이해도는 `설명 필요 / 일부 시스템 학습 중 / 해당 분야 익숙함 / 미확인` 정도로 별도 판단한다. 예를 들어 기반은 숙련 단계여도 새 보스 패턴 설명은 입문 수준으로 할 수 있다. 단계를 사용자에게 등급표처럼 들이밀지 말고 “지금은 다음 보스 전환보다 기본 코어를 채우는 쪽부터 비교하겠습니다”처럼 선택 이유를 설명한다.

## 4. 이번 판단을 유지·수정하기

내부적으로 `이번 목표 → 성장 단계와 근거 → 이해도 → 시간·예산 → 주된 병목 → 적용 reference → 남은 불확실성`을 정리한다. 원자료의 기준일을 연결하고, 사용자가 수정을 주면 기존 추정보다 우선한다. 캐릭터 변경·기간제 만료·해방·새 패치·목표 변경이 있으면 해당 축을 다시 확인한다.

계획에는 다음 행동, 비용/시간, 목표에 도움이 되는 이유, 멈출 조건 또는 다음 단계로 넘어갈 조건을 넣는다. 예산·규칙·교체 후 스탯이 불명확하면 숫자 순위를 만들지 않고 확인한 병목부터 조건부 제안한다. 일시적인 이벤트 보상만으로 장기 계획을 완성하지 않는다.

사용자가 직접 말한 목표·예산·시간·경험은 `update_player_context`로 저장한다. 단계·이해도·확신도는 LLM의 잠정 해석으로 `record_growth_assessment`에 분리해 저장할 수 있다. 이전 판단의 `needs_review`·시각·근거를 확인하고, 변경되거나 오래된 정보는 재진단한다. 저장 절차와 revision 검사는 [state 갱신 지침](state.md)을 따른다.

## 경계 사례

| 상황 | 적절한 분기 |
| --- | --- |
| 버닝으로 높은 레벨이지만 링크·코어가 비고 보스 경험이 없음 | 기반 구축 전략 + 쉬운 설명; 높은 레벨만으로 중급 처리하지 않음 |
| 숙련자가 새 부캐를 키우며 낮은 단계에서 주차하려 함 | 기반 구축 전략 + 간결한 설명 + 주차 목표; 본캐 종결 세팅을 복사하지 않음 |
| 장비는 좋지만 프리셋·특수 반지 사용을 처음 배움 | 해당 성장 단계의 투자 기준 + 그 시스템의 입문 설명 |
| 스펙은 충분한데 목표 보스에서 자주 사망함 | 해당 단계 + 보스 운영/연습 분기; 딜 투자부터 확정하지 않음 |
| 복귀자가 옛 리부트 경험과 현재 KMS 장비를 혼용함 | 최신 규칙·월드·패치 차이부터 확인, 경험과 현재 기반을 분리 |
| 하루 20분, 코디 중심이며 현재 보스에 만족함 | 시간·취향 분기, 현재 상태 유지도 유효한 결론 |
| 전후 스탯이 주어진 계산만 요청함 | 계산 reference만 사용; 전체 성장 진단과 계정 조회 생략 |
| 이름·목표·현재 상태가 모두 불명확함 | 단계 미확인, 짧은 확인 질문과 일반 원칙만 제공 |
