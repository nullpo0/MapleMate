# 장비 구매·교체 효율 상담

“이거 효율 어때?”, “이 가격에 살까?”, “이 장비로 바꿀까?”는 옵션 감상으로 끝내지 말고 **현재 장비 대비 증가분·비용·목표에 맞는 대안**을 함께 판단하는 요청으로 처리한다. 최종뎀 계산은 사용자의 추가 질문을 기다리지 않고 진행한다. 사용자에게 실제 구매나 판매를 대신 실행하지 않는다. 계산 규약은 [damage.md](damage.md)를 따른다. MCP guide topic은 `equipment`이며 계산 규약도 함께 제공한다.

## 첫 질문에서 진행할 일

매물 이미지·가격·기존 장비·캐릭터·목표·사용 가능한 계산 입력을 먼저 모은다. 이미 대화나 state에 확인된 값을 다시 묻지 않고 시각과 조건을 확인한다. 이미지를 첨부했으면 우선 그 이미지를 판독한다. 첨부 없이 현재 게임 화면 확인을 요청했을 때만 한 장 캡처한다. pasted 대화·테스트 사례는 현재 구매 요청이나 새 캡처 요청으로 취급하지 않는다.

캐릭터가 확인되면 `get_player_state`로 목표·예산·저장 데이터의 시각을 확인하고 `get_damage_calculation_context`에 필요한 `item-equipment` 등을 추가해 현재 장비와 스탯을 모은다. 이미 같은 기준일의 API를 조회했다면 `refresh=False`로 재사용하고 실패·누락 때만 해당 항목을 보완한다. 보관값을 실시간 상태라고 표현하지 않는다. 전체 계정과 모든 API를 수집하지 않는다.

같은 슬롯의 착용 장비와 매물을 대조한다. 세트·고정 옵션·% 옵션·추가 잠재·교환 조건에서 **잃는 효과와 얻는 효과**를 함께 반영한다. 현재 장비 대비 변화량을 계산하여 `calculate_final_damage_option_gain` 또는 확인한 전후 프로필의 `calculate_final_damage_gain`을 호출한다. 동일 조건에서 상쇄되는 항은 계산 규약의 정규화 조건을 밝히고, 변하는 직업 효과·스킬·세트는 별도로 검증한다. 계산 도구가 있는데 LLM 암산만으로 최종뎀 숫자를 제시하지 않는다.

가격이 있으면 도구의 최종뎀 증가율과 함께 비용당 증가율을 계산한다. 사용자용 표기는 `최종뎀 1%당 비용 = 비교 비용 / 증가율(% 단위)`다. `1.116%`는 0.01116이 아닌 1.116으로 나눈다. 증가율이 0 이하이면 이 지표를 정의하지 않는다. 기존 장비 판매 회수·거래 비용이 확인되면 순투자비로 비교한다. 회수액이 없으면 **구매가 기준**이라고 밝히고 순비용이라고 부르지 않는다. 확인되지 않은 회수액을 0으로 가정하여 순비용을 확정하지 않는다.

## 입력이 부족하면 한 번에 요청

API·대화·state로 얻을 수 있는 정보부터 확인한 뒤 실제 변화 계산에 필요한 누락값을 묶어 요청한다. 누락 목록을 도구 필드명 그대로 사용자에게 던지지 않는다. 스탯% 옵션이면 해당 주·부스탯의 % 증가량과 %미적용 수치, 공/마 옵션이면 공/마 상세값을 읽을 수 있는 툴팁을 구체적으로 안내한다. 반지 가격·캐릭터·목표 등이 이미 확인됐으면 다시 묻지 않는다. 대안의 모든 입력까지 한꺼번에 요구하여 상담을 막지 않는다.

예: “매물과 기존 링 차이는 확인했어요. 실제 딜 증가율을 계산하려면 INT·LUK·마력 상세 툴팁의 % 증가량과 %미적용 수치가 필요해요. 세 툴팁을 보여주시면 500억 대비 효율까지 함께 비교할게요.” 이는 해당 옵션이 세 스탯에 영향을 주는 사례다. 다른 장비에도 항상 세 툴팁을 요구하지 않는다.

자료가 오면 사용자가 다시 ‘최종뎀 계산해줘’라고 말하지 않아도 **판독 → 계산 → 비용 비교 → 대안 검토 → 구매 판단**을 이어간다. 이미 답한 옵션 차이와 일반 설명을 길게 반복하지 않는다. 추가로 발견된 중요한 불명확값은 다시 묻되, 근거를 생략하기 위해 질문 횟수에 고정 상한을 두지 않는다.

입력이 부족한 첫 답변은 확인된 차이, 어떤 값이 부족한지, 그 값으로 무엇을 비교할지를 짧게 말하고 필요한 자료를 요청한다. 실제 계산·시세·대안 비교 전에는 “500억에 비효율”, “급히 살 필요 없음”, “좋은 매물” 같은 구매 우열을 확정하지 않는다. 사용자 목표가 생존·원킬·유틸이면 해당 지표로 먼저 판단할 수 있으며 딜 증가율만 강요하지 않는다.

## 현재 캐릭터에 맞는 대안 검토

현재 장비·내실·목표에서 병목을 확인하고 질문에 필요한 범위의 후보를 선택한다. 약한 부위 교체, 현재 HEXA 한 단계, 확인된 무료 조정, 기존 장비 유지 등이 가능하지만 목록 전체를 매번 나열하지 않는다. 목표와 무관한 딜 증가를 대안의 장점으로 삼지 않는다. 숙련자의 작은 옵션 교체 상담에 뉴비 루틴부터 다시 안내하지 않는다.

실제 후보의 전후 효과와 비용을 확보하면 같은 캐릭터·버프·대상·가격 기준으로 각각 계산해 비교한다. 매물·시세 조회는 클라이언트 검색 또는 사용자가 준 정보로 수행한다. Nexon 장비 API가 경매장 가격을 제공한다고 표현하지 않는다. 현재 시세를 검색했으면 월드·시각·실매물/실거래 여부를 밝힌다. 검색 수단이 없거나 다른 후보의 가격이 없으면 “다른 부위가 더 낫다”는 순위를 만들지 않는다.

다른 대안의 가격·효과가 부족하면 현재 확인된 장비에서 구체적인 비교 후보를 짚고 **같은 효율을 내는 기준선**을 제시할 수 있다. 구매가 기준 현재 증가율을 g%, 가격을 C라 하면 비용 c인 후보는 `g×c/C%` 이상 증가해야 비용당 딜 효율이 같거나 높다. 모델 밖 효과·순투자비 차이도 함께 고려한다. 이 기준선은 대안이 실제로 그 효과를 낸다는 주장이나 적정 시세가 아니다. 실제 후보가 전혀 확인되지 않으면 유지 선택과 추가 비교 항목만 제시한다.

## 결과를 짧게 전달

입력이 충분한 첫 답변은 증가율·가격 대비 효율·검증된 비교 결과를 먼저 말한다. 필요하면 작은 후보 표를 쓰고 목표와 관련된 이유를 덧붙인다. 내부 도구 순서, 전체 스탯 산식, 같은 경고를 반복하여 답변을 늘리지 않는다. 자세한 계산은 요청할 때 설명한다.

아래는 사용자가 제공한 테스트 결과를 답변 형식으로 정리한 예이며, 매물을 재조회하거나 수치를 새로 검증한 결과가 아니다:

“제공된 조건에서는 교체 시 약 1.12% 상승하고, 500억 구매가 기준 최종뎀 1%당 약 448억이에요. 다른 200억 후보가 약 0.45% 이상 올려준다면 딜 효율은 비슷하거나 더 좋습니다. 현재 확인된 후보의 실제 증가율과 가격을 같은 조건으로 비교해 투자 순서를 정하겠습니다.”

실제 상담에서는 확인된 비교 후보와 결과로 문장을 완성한다. 후보가 없는데 비교를 끝냈다고 말하지 않는다. 정확한 수치가 나와도 목표 보스 클리어·예산 내 강화 성공을 보장하지 않는다. 최종 판단은 계산된 증가분, 예산, 목표의 병목, 교환·회수 조건과 확인된 대안을 함께 근거로 삼는다.
